chat, then agent

A chat answers. An agent does the work.

In a plain chat, the model writes text and you do everything else: copy the code, save the file, test it. An agent is the same model given tools, like reading files, running commands and searching the web, plus a loop: look, decide, act, check, and go again until the job is done.

That's how this chapter got built. The agent read my live repo, wrote the page, ran the syntax checks, the fit check and the Breaker, handed the result to a second agent to review, fixed what it found, and zipped the files for me to upload. My part was the brief, the decisions, and the upload.

skills

Saved instructions it loads when they fit

A skill is a saved set of instructions for one kind of job. The agent keeps a one-line description of each skill in view and only reads the full instructions when a task matches. That way my rules come back in every new session, without filling the desk with all of them at once.

Here are five of mine. For each task, pick the skill that should load.

schedules

A job that runs while you sleep

A scheduled task starts an agent on its own, on a timer. Two things make it different from a chat: every run starts fresh, with no memory of earlier chats beyond any short notes a memory feature puts back, and nobody is there to say yes or no. Set one up and see if it would work.

Every chapter since Chapter 11 went through a second agent that hadn't seen it being built. Its only job was to find what's wrong and prove it. These are real catches from building Chapters 11 to 14 on Nov 13. Tap each card to see what the builder thought, and what the reviewer found.

Why a fresh agent sees more

The builder knows what it meant to write, so it reads its own work the way it intended it. The reviewer only has the page and the code, the same as a stranger. It's the Chapter 12 lesson again, aimed at the AI.
